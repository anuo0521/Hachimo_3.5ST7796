# Firmware repair baseline

This folder remains based on PC-bundled 0.7.103, not the experimental 0.7.108 branch.

Public revision `0.7.103-p4-r2` accompanies desktop `0.1.168` as a maintenance
release. Experimental framework work is not part of this build.

The factory and OTA bootstrap catalogs contain 28 built-in components, with
`cloud-hop` as the factory default. Launcher thumbnails are regenerated from the
same catalog. Generic media parsing, rendering and playback remain available;
their regressions use isolated synthetic fixtures, not a bundled live service.

`main/pet_p4_miniapp.c` owns transactional component storage and per-component recovery from verified committed catalogs. Navigation persists only the last-opened ID, leaving the previous catalog available for recovery. Unparseable existing catalogs block destructive bootstrap reseeding. Known image-free bootstrap packages are distinguished from complete resources.

`main/pet_p4_protocol.c` exposes resource integrity and bounded resource-repair installation. Repairs retain component records and existing button configuration, and refuse writes during audio activity. `tools/build_builtin_bundle.py` emits bootstrap identity checks without inflating the bundle. `tests/component_resource_recovery_test.py` executes production recovery logic with sanitizers; fault injection belongs in offline tests, never on user storage.

`components/esp_lcd_st7796/` is a local `esp_lcd_panel_t` driver for the
replacement 鸿讯 CL35BC1017-40A 3.5" module (ST7796S, 320x480 glass, FT6336U
touch). It speaks only the generic `esp_lcd_panel_io_t` calls, so the transport
is chosen entirely by `main/pet_p4_lcd.c`: the default is an 8080 8-bit
parallel bus driven by LCD_CAM, with 4-wire SPI and the original Waveshare DSI
BSP kept as alternatives. `main/Kconfig.projbuild` owns every pin. On the
parallel path `flags.swap_color_bytes` makes the peripheral swap RGB565 byte
order during DMA, so the frame buffer streams out of PSRAM with no staging copy;
the SPI path still needs the 16-row swap buffer because the serial data phase
cannot reorder bytes. `main/pet_p4_panel.h` collapses the two ST7796 transports
into one `PET_P4_PANEL_ST7796` so callers never test the bus. `bsp/display.h`
reports 480x320 because the driver sets MADCTL MV, and
`main/pet_p4_renderer.c` fits the 640x480 UI into 424x320 at a 28 px offset so
the pet keeps its proportions.
`main/pet_p4_panel_geometry.h` is the single source of that fit: the renderer
draws with it and `main/pet_p4_touch_core.c` inverts it, so retuning the
letterbox can never desynchronise touch from what is on screen.
